- (constraint) Inherited AD-2/AD-3: repos solo instanciables desde server-only code, via factory.ts (unico punto de resolucion). getXRepository(): Promise<IXRepository> con firma async desde dia uno; DATA_SOURCE=mock|api selecciona implementacion, valor no reconocido = error fail-loud
- (constraint) Inherited AD-4: validacion zod en el borde (server actions), antes de invocar usecase
- (constraint) Inherited AD-5: estado derivado (balance, isNearLimit, isOverBudget, variacion mensual) vive en usecases, nunca se recalcula en componentes
- (constraint) Inherited AD-6: utilidades compartidas solo en src/lib/, no carpeta shared/ paralela
- (constraint) Inherited AD-7: IDs de entidad via crypto.randomUUID(), asignados dentro de create() de la implementacion de repositorio, nunca en usecase/presentacion
- (constraint) Inherited AD-8: app/globals.css unica fuente de tokens de diseno
- (constraint) Inherited AD-9: next.config.ts nunca output:export -- Server Actions incompatibles con static export; deployment requiere host con runtime Node.js
- (constraint) Inherited conventions: ActionResult<T> = {success:true,data:T}|{success:false,error:string} para errores esperados; throw reservado para redirect()/notFound(); errores zod unidos en string legible; excepciones de repo mapeadas a mensaje curado, nunca e.message crudo al cliente
- (decision) Hosting: Vercel Hobby (free). Verificado en vercel.com/docs/plans/hobby: 100GB fast data transfer, soporte nativo Next.js App Router/Server Actions sin adaptador, uso personal no-comercial permitido. Alternativas descartadas: Railway (free tier reducido a 1USD credito/mes, no viable), Render (spin-down 15min inactividad + Postgres free expira a 30 dias), Cloudflare Workers (requiere adaptador OpenNext, riesgo de compatibilidad con Next.js 16.2.2), Netlify (tambien viable pero Vercel elegido por predictibilidad de limites concretos vs sistema de creditos abstracto)
- (decision) Base de datos: Supabase (Postgres + auth + storage). Verificado: free tier 500MB storage, 50K MAU auth, 1GB file storage, 500K edge function invocations, limitado a 2 proyectos. Elegido sobre Neon (mas espacio/proyectos pero sin auth/storage incluido) por incluir auth y storage para uso futuro (ej. login, adjuntar recibos) sin agregar otro servicio
- (version) Vercel Hobby plan (verificado vercel.com/docs/plans/hobby, 2026-08-17); Supabase free tier (verificado via busqueda web, 2026-08-17)
- (decision) Data access: solo @supabase/supabase-js (cliente de Supabase), sin ORM separado. Tipos via 'supabase gen types typescript'. Confirmado por usuario sobre alternativa Drizzle+supabase-js dual
- (decision) Auth: Supabase Auth activado desde el dia 1, multi-usuario. Confirmado explicitamente por usuario tras aclarar el trade-off (vs diferir a single-user)
- (decision) Scoping de usuario: via Row Level Security (RLS) en Postgres (auth.uid() = user_id, policies con 'TO authenticated'), NUNCA userId explicito pasado a metodos de repositorio. factory.ts obtiene cliente de Supabase autenticado por request (via @supabase/ssr createServerClient + cookies de next/headers) y lo inyecta en cada Api*Repository. Interfaces IXRepository no cambian de firma. Previene: un repo implementado a mano olvidando el filtro de usuario y filtrando datos de otro usuario
- (decision) Requiere middleware.ts en la raiz para refrescar tokens de auth (@supabase/ssr, Server Components no pueden escribir cookies)
- (version) @supabase/ssr (reemplaza @supabase/auth-helpers, deprecado) -- verificado supabase.com/docs/guides/auth/server-side/nextjs, 2026-08-17
- (decision) Migraciones de esquema: Supabase CLI (supabase migration new, supabase db push). No hay ORM que gestione migraciones
- (decision) SUPABASE_SERVICE_ROLE_KEY nunca se usa en la app (ni factory.ts ni server actions) -- bypasea RLS. Solo SUPABASE_ANON_KEY + sesion del usuario via @supabase/ssr. La service_role key no se define como env var en Vercel
- (decision) Un solo proyecto Supabase compartido dev/prod (no environments separados) -- free tier limita a 2 proyectos, no vale gastar uno en staging para uso personal. Confirmado por usuario
